## 记事本中文渲染 + 数据盘挂载修复（2026-11-11）

用户报告两个 bug：记事本中文渲染仍有问题；数据盘识别不到/没挂上。全部修复并 QEMU 实测通过（串口标记 + 截图「你好」清晰渲染）。

### 根因链（共 6 处）
1. **DrawLines 双编码**（`csharp/apps/mex/Notepad/Program.cs` + `csharp/apps/Shell/Apps.cs` 壳内置记事本同款）：MiniCLR 字符串是 UTF-8 字节数组，`s[j]` 是字节；旧代码逐字节 `Host.CharStr(s[j])` 把每个字节再 UTF-8 编码（E4→C3A4），`draw_text_utf8` 命中"2字节→跳过"分支 → 中文整体消失。修法：`U.Sub(s,start,i-start)` 整段直传。
2. **TBox.Insert/Backspace/Delete/GetSelection 逐字节重建**（`csharp/NexOS.Forms/Forms.cs`）：插入第二个汉字时把缓冲区里已有的中文逐字节再编码（实测 55→61 chars、buffer 损坏、退格后仍乱）。修法：全部改 `Sys.StrSub` 字节切片重建；Backspace/Delete 改为按码点（回退 continuation 字节）删除。
3. **宽度模型逐字节**：GlyphAdv/NpWidth 每字节算 16px → CJK 光标偏 3 倍。改为 `GlyphAdvOf/Utf8Consume`（NpAdv/NpBytes）解码序列。
4. **IME 词典候选序**（`ime_dict.h`）："hao" 首候选是 毫(0x6BEB) 不是 好(0x597D)，空格上屏错字。已调序。注意 Makefile 无头文件依赖，改 ime_dict.h 后须 `touch src/gui/gfx_ime.cpp src/gui/gui_legacy.cpp` 再 make。
5. **数据盘扫描顺序**（`kernel.cpp ata_find_hdd`）：原顺序 副-master→副-slave→主-master→主-slave，QEMU 双 `-drive` 时数据盘在 primary slave，主 master（=启动盘）先被找到 → MKFS 挂了启动盘 LBA900 空白区 → "Not formatted"（真机此前"能挂"其实挂的是启动盘上历史 mkfs 的残留）。修法：扫描序改为 sec-m→sec-s→**pri-slave→pri-master**，启动盘只作最后回退。验证：`[MKFS] Data disk: ATA primary slave / Mounted, data area (user data disk) / mounted (1 files)`。
6. **MKFS 超级块首读竞态**：新检出盘的首次读偶发返回垃圾 → 间歇 "Not formatted"。`Mfs::init()` 加 3 次重试 + settle 延迟（串口打 "[MKFS] superblock retry N"）。

### 其他要点
- MiniCLR 铁律再确认：字符串 = UTF-8 字节数组，一切逐字符 `Host.CharStr(s[i])` 处理已有文本都是错的；正解 `Sys.StrSub` 字节切片。
- `Gfx.Text` 链路：`g_text`→`clip_text`（按字节正确）→`mh_text`→`draw_text_utf8_transparent`→`draw_cjk_transparent`（矢量 msyh 优先→24x24 位图→内嵌 16x16，找不到画方框），内核侧推进 `cx+=draw_cjk(...)` 无问题。
- 验证脚本 `tools/verify/test_ime_v2.py`（启动等待已改轮询串口 `mforms: entry`，最多 150s）+ `tools/verify/run_ime_v2.sh`，QEMU `-m 1024 tcg`。shell.mex 偶发 "CLR fault: truncated image"（SFS 首读毛刺，先在问题）会导致整次 run 失败，复跑即可。
