## AI 输入窗口打不了字 —— 根因修复 + 端到端验证（PASS）

### 根因（用户纠正：是 AI 输入窗口，不是 notepad）

## 【重大】发送指令后白屏 + 状态栏消失 + 退化成"简洁版桌面"且切不回 —— 根因与修复

用户实测：AI 桌面输入指令回车后，屏幕直接没字、状态栏消失、切回去变成简洁版桌面、再也切不回来。
用户同时指出此前的无头测试只能发现"简单的编译错误"，并要求**不要再跑 test_ai_*.py**，直接读代码定位。

### 根因（三层，全部代码级确认，不是重启/不是三重错误）
1. **粘性死亡开关（决定性）**：`clr.cpp::clr_call()` 原来在任何一次失败时执行 `g_resident = 0`（"stop calling
   into a broken image"）。`clr_loaded() = g_resident && !g_fault`，`mforms_ready() = g_ready && clr_loaded()`。
   于是**单次 fault 就把托管 shell 永久下线**：
   - `mforms_paint_desktop/overlay` 直接 return → 桌面无字、**任务栏/状态栏消失**
   - `mforms_has_desktop()` 返回 0 → `gui.cpp::render_all` 走 `draw_wallpaper/draw_topbar/draw_portal_desktop`
     → **原生"简洁版桌面"**
   - `mforms_desktop_key` 直接 return 0 → Ctrl+←/→ 切桌面失效 → **再也切不回 AI 桌面**
   `g_fault` 同样粘性：它只在 `clr_call` 开头清零，而所有 mforms 入口在调用前先查 `mforms_ready()`，
   一旦 latch 住就再没有 `clr_call` 去清它 → 二次死锁。
2. **触发 fault 的真凶：托管侧 O(n²) 字符串炸弹**（CLR 堆是 512KB bump 分配器，无 GC）
   - `Desktop.AiSend`：两个 `for(...) r = U.Cat(r, Host.CharStr(...))` 循环（平铺换行 + 截断 700）。
     `agent run` 输出约 2KB → 分配量 ≈ n²/2 ≈ **2MB** → "managed heap exhausted" → fault。
     这就是"输入指令后立刻白屏"的精确位置。
   - `Desktop.AiDrawMsgAt`：逐 codepoint `U.Cat` 拼每行，**每帧**对每条可见消息重跑。
     单行 77 字符 ≈ 4.5KB，6 行/条 × 16 条 ≈ **432KB/帧** → 历史一多每帧都 fault。
3. **失败后堆水位不回滚**：`mforms_key/desktop_key/click/...` 的失败分支直接 return，
   不 `clr_heap_reset`，堆仍是满的 → 下一次调用第一个分配就再 fault（自锁）。
   更糟：`mforms_close` 原来**无条件** `rebaseline()`，会把炸掉的水位烙进持久底线永不归还。

### 改动
- `clr.cpp`
  - 新增原生 icall `NexOS.Sys::StrSub(s,start,len)` / `NexOS.Sys::StrFlat(s)`（各 1 次分配），
    并注册进 `g_icalls[]`。**以后托管侧一律禁止用逐字符 U.Cat 建串。**
  - `clr_call` 失败不再立刻 `g_resident=0`：改为连续失败计数 `g_fail_streak`，
    达到 `CLR_FAIL_STREAK_MAX=12` 才卸载；可恢复路径显式 `g_fault = 0`（否则 latch 死锁）。
    成功时清零计数；`clr_load` 也清零。
- `mforms.cpp`：新增 `heap_recover()`（回滚到 `g_persist` + 串行日志），
  接到 `mforms_open/close/click/key/desktop_key/desktop_click/desktop_rclick/rclick` 的全部失败分支；
  `mforms_close` 改为**仅成功时** `rebaseline()`。
- `Sys.cs` / `Forms.cs`（`U.Sub`/`U.Flat`）/ `winhost/Backend.cs`（WINHOST 侧 shim）同步声明。
- `Desktop.cs`
  - `AiSend`：先 `U.Sub` 截到 480 字节（UTF-8 边界回退，避免撕裂多字节）再 `U.Cat "..."` 再 `U.Flat`，
    合计 3 次分配（原 ~2MB）。480 也正好是 6 行能显示的上限。
  - `AiDrawMsgAt`：改为**每行一次 `U.Sub` 切片**（原每字符一次 Cat），~500B/条（原 ~27KB/条）。
  - 输入上限 `200 → const AiCodeMax = 96`：`AiCodeToString` 仍是逐 codepoint 拼接（int[] 类型的 icall
    MEX 编译器不支持），每帧跑一次，96 个 CJK ≈ 41KB/帧可接受，200 个 ≈ 180KB/帧会炸。
- `ai_engine.cpp`（纵深防御）
  - `MarkovModel::alloc()` 改返回 `bool`：原来 kmalloc 失败仍 `ai_memset(NULL, 0, 4MB)` → 页错误 → 三重错误。
  - `markov_train/markov_predict` 加 `!m->transitions` 判空。
  - `transformer_forward` 改返回 `bool`，7 个 kmalloc 全判空并在失败时全量 kfree（单次 pass 约 145KB scratch）。
    `ai_generate` 里 `if (!transformer_forward(...)) break;`；`ai_transformer_test` 同步处理。
  - `ai_generate` 增加 `use_transformer && !model` / `!use_transformer && !markov.transitions` 与 output kmalloc 判空。
  - `ai_init` 失败时释放已分配资源并 `initialized = false`。
  - `AGENT_GEN_TOKENS`：`agent_execute` 的生成步数 **100 → 24**（每 token = 1 次完整 forward，
    100 步 × 多任务在裸机上会把 GUI 冻死几十秒且完全不重绘，观感就是"屏幕没字"）。
- `kernel.cpp::cmd_agent`：`init` 分支改为检查 `ai_init(...) != 0` 就报错返回，
  不再无视返回值把 `g_ai_initialized` 置真（否则后续 run 拿 NULL model 去推理）。

## AI 回复打字机效果（逐字显示）

用户要求：AI 回复像打字机一样逐字显示出来（非一次性整段出现）。

### 实现（全部在 `csharp/apps/Shell/Desktop.cs`）
- 新增状态字段：`aiTypeFull`(完整回复串) / `aiTypePos`(已显示**字节**偏移) / `aiTypeActive`(是否正在打) / `aiTypeTick`(上次推进的 `Host.Ticks()`)。
- 新增常量 `AI_TYPE_STEP_CP=2`（每步推进的码点数）、`AI_TYPE_STEP_TICKS=24`（每步间隔 tick，约一个光标闪烁半周期）。
- 新增 `AiTypeTick()`：每帧由 `AiDesktopPaint` 调用，按流逝 tick 把 `aiTypePos` 用 `U8Next` 推进 `AI_TYPE_STEP_CP` 个**码点**（字节游标，绝不会切裂 CJK 多字节序列）；追帧的 while 在两帧间隔过大时也能追上，但到串尾即停。
- `AiSend`：拼好 `reply = "AI: "+res` 后 `AiHistAdd(reply)` 并置 `aiTypeFull=reply; aiTypePos=0; aiTypeActive=1; aiTypeTick=Host.Ticks()`。
- `AiDesktopPaint` 历史绘制循环：当 `aiTypeActive!=0 && k==aiHistN-1`（最新一条 AI 回复）时，画 `U.Sub(aiTypeFull, 0, aiTypePos)` 这段已显示前缀，而非整条；其余历史照旧整条画。打完（`aiTypePos>=长度`）`aiTypeActive=0`，自动恢复整条显示。

### 关键约束（踩坑点）
- `U.Sub` 在真实 OS 是**字节**切片（`ic_str_sub` 用 `str_len`/字节偏移），而 `U8Next` 算的是**码点**——所以动画游标必须用**字节偏移 + U8Next 推进码点**，绝不能直接拿码点数当 len，否则 CJK 会被切裂。
- 堆安全：每帧 `mforms_paint_desktop` 会 `clr_heap_mark`→`clr_heap_reset`，堆每帧重置，故每帧一次 `U.Sub(aiTypeFull,0,aiTypePos)` 不会累积。`AiTypeTick` 本身不分配，仅整数/游标运算。
- WINHOST 预览桩 `StrSub` 已自带 `start+len>n` clamp，CJK 在预览里会直接显示全文（不崩，仅预览观感不精确），无需改动。

## 【紧急修复】AI 桌面每帧 `[CLR] fault: unsupported IL opcode 0x12` → 整块空白 + 加"思考中…"指示器

用户实测打字机版后：AI 桌面每帧刷 `[CLR] fault: unsupported IL opcode 0x12`，界面啥都没有；要求至少加个"在思考中"提示。

### 根因（代码级确认）
- `0x12 = ldloca.s`：MiniCLR 解释器**不支持 `out`/`ref` 参数**（局部变量取地址）。`clr.cpp` opcode 分派里
  `0x11`(ldloc.s)/`0x13`(stloc.s) 有 case，`0x12` 没有 → 落到 default 报 `unsupported IL opcode 0x12`。
- 打字机版引入的 `U8Next(s, i, out cp)` 用 `out cp` 取地址 → 编译（MEX 编译器接受 C# 的 `out` 语法）
  但**运行时**每帧调 `U8Next(out cp)` 就 0x12 fault。
  关键：历史为空时 `AiDesktopPaint` 的 `for(k=aiHistN-1...)` 循环根本不执行，故之前没炸；
  一旦有消息（You:/AI:），循环每帧都跑 → 每帧 `U8Next(out cp)` → 每帧 fault → AI 桌面整块空白。

### 改动（全部 `csharp/apps/Shell/Desktop.cs`）
- **`U8Next` 去掉 `out`**：改返回字节游标、码点经静态暂存字段 `g_u8cp` 传出（`static int g_u8cp; static int U8Next(string,int)`）。
  三个调用点（`AiMsgLines`、`AiDrawMsgAt`、`AiTypeTick`）同步改为 `int next = U8Next(s,i); int w = CpWidth(g_u8cp);` 形式（不再 `out cp`）。
- **全树排查**：`grep -rn '\b(out|ref)\s+\w+' csharp` 仅 `winhost/Backend.cs:256`（`out Bitmap bmp`，WINHOST 是 Windows .NET 预览桩，支持 out，不参与 MEX 编译）一处，
  OS 路径（`Desktop.cs`/`Forms.cs`/`Sys.cs`/`Gfx`/`U`）已无 `out`/`ref`。
- **"思考中…"指示器**：`AiSend` 不再同步阻塞调 `agent run`，改为先 `AiHistAdd("AI: 思考中…")` + 置 `aiThinking=1` + 缓存 `aiPendingGoal`。
  新增 `AiRunPending()`：在 `AiDesktopPaint` **末尾**（`if(aiThinking!=0) AiRunPending();`，即"思考中"已绘制后才跑）执行
  真正阻塞的 `Host.Exec`，并用占位那条替换为真回复、启动打字机；`aiThinking` 在函数开头先清 0 防 fault 重试死循环。
  绘制循环里 `aiThinking!=0 && k==aiHistN-1` 时对最新条动画 `AI: 思考中` + 0/1/2/3 个点（`(Host.Ticks()/25)%4`）。

### 验证（按用户要求：只做构建 + 静态排查，不跑 QEMU 测试脚本）
- WSL `make -B` EXIT=0，`shell.mex` 重打包(75667B)、`os.img` 4MiB 正常生成。
