端到端跑通：远程桌面把 Linux 兼容层桌面 app 渲染到帧缓冲 → 经 HTTP 压缩为 NXFB 取帧 → 输入回注。用「我的世界启动器」`usr/mc_launcher.c`（freestanding ELF32，syscall 400 取 fb / 401 等输入）测试。

### net.cpp 三处根因修复（前序 + 本会话）
1. **TCP 校验和字节序**（前序修，保留）：`tcp_checksum` 用 host-order IP 拆分 + `0x0006` 协议字 + 原生 len + 大端读段字节 + `htons` 返回。
2. **NE2000 接收长度含 4 字节以太网 CRC**（本会话根因）：原 `payload_len = len - ihl` 用 NIC 帧长（多 4B）→ guest `ack` 比 host 真实 SND.NXT 多 4 → RFC 793 下 host 把数据段判为"不可接受"丢弃，HTTP 响应永不到 host。→ 改用 IP 头 `total_len` 权威解析：`ihl=(ver_ihl&0xF)*4; iplen=ntohs(ip->total_len); payload_len=iplen-ihl`（`handle_ip`）。
3. **`parse_int_param` token 跳跃 bug**（本会话根因）：原 miss 时跳到下一 `&`，使首 token 里的 key（如 `/input?mx=512` 的 `mx`）恒匹配不到返回 0 → 输入坐标错、PLAY 按钮不响应。→ 改为逐字符扫描（`while(*p){ if match key'=' ...; p++; }`）。
4. **TX 队列扩容**：`#define TXQ_SLOTS 8 → 64`（`/screen` NXFB ~62 段，8 槽丢尾段）。`nic_send` 与 NE2000 接收共用远程 DMA，禁止在 `nic_receive` 内嵌套发送；所有出站包经 `tx_enqueue` → `net_poll` 末尾 `tx_flush`。
