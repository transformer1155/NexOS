## 终端改造交付到 VM（2026-08-21 续）
- **MiniCLR 编译约束是真正拦路虎**：WinHost（full .NET BCL）编译 0 error，但 `Shell.csproj` 走 `/nostdlib` 仅 MiniCLR corlib。`string +` 运算符、`Substring/IndexOf/Insert/Remove/Trim/ToLower/StartsWith/char.IsLetterOrDigit/StringBuilder` 全部不可用（CS0656 / 缺方法）。`TerminalApp` 最初用了一堆这些 → 编译失败。
- 改写为 mini-BCL 惯用法（两种构建都能过）：
  - 单字符拼接走 `Host.CharStr((int)ch)`；字符串拼接走 `U.Cat`（2..7 参重载，注意 6 参未在 stale DLL 命中——直接用 7 参或嵌套 3+4 参）。
  - `Substring(a,b)` → `U.Sub(s,a,b)`；`IndexOf`/`StartsWith`/`Trim`/`Lower` 自写小 helper；`Insert/Remove` → `InsStr/DelStr`（U.Sub 组合）；`StringBuilder` → 渲染直接读 `char[] ch`（PR 类改存 `ch/fg/bg/len`，不再存 `txt` 字符串，规避 O(n²) 堆爆）。
  - `ParseLine` 直接填 `char[] ch` + 每字符 `fg/bg`，不再 `StringBuilder.ToString()`。
  - 关键坑：`U.Cat` 6 参在 MiniCLR 下解析到 7 参重载并缺 `g` 报错 → 该调用补第 7 个 `""` 即可。
  - 大数组 `gLine/gChar` 从 `new int[200000]` 降到 `GRIDCAP=65536`（256KB/数组，够 256×256 格，远超 4K 终端），`ComputeLayout` 填格循环加 `b+c < GRIDCAP` 守卫、`gN` 钳到 `GRIDCAP`，彻底排除越界。

## Linux 兼容层大修 — busybox 真机级运行（2026-08-21 续）
- **目标**：让 SFS 里的真实 busybox 静态 ELF32 在 NexOS linux 兼容层里跑起来（此前只跑通自研 linuxhello）。
- **关键修复**（`linux_compat.cpp`）：
  1. **mmap cursor 守卫逻辑 bug**：原 `g_mmap_cursor - alloc < 0x0C000000` 从 192MiB 起每次必 ENOMEM。改为游标从映射区顶部 0x0F000000（240MiB）向下、下限 MMAP_FLOOR=0x0A000000（160MiB，避开 argv 字符串区）。
  2. **brk 起点错误**：原固定 0x04000000（撞内核堆 0x500000）。改为数据段末尾 `(max_end+0xFFF)&~0xFFF`，上限 0x09000000（字符串区之下）。
  3. **启动栈缺 auxv**：原只放 argc/argv/NULL/NULL，glibc/musl 静态二进制 `__libc_start_main` 依赖 AT_PHDR/PAGESZ/ENTRY/RANDOM/EXECFN → 崩溃。补全 15 项 auxv + 最小 envp（PATH/HOME/TERM 等）。
  4. **匿名页必须清零**：Linux mmap(MAP_ANONYMOUS)/brk 契约返回零页；返回脏内存导致 glibc malloc chunk 校验失败 → `hlt` 死机（busybox pwd 卡死根因）。mmap/mmap2/brk 分配后逐字节清零。
  5. **栈位置**：原栈顶紧贴 ELF 上方（0x08150000）→ brk 堆只剩 4KB。改到 0x0E000000（224MiB），brk 堆解放到 144MiB。**注意**：QEMU 必须 ≥224MiB 物理内存（测试脚本统一 256M，128M 会 #PF）。
  6. **hex 打印 bug**：`for(s=28;s>=0;s-=8)` 错位，改 `s=24`（调试期曾因此误读 mmap2 flags 为 0x03 实为 0x32）。
  7. **新增 syscall**：63 dup2、64 dup、205 getgroups32、221 fdatasync、265 faccessat2、116 sysinfo、239 openat2、11 **execve**。
- **execve + busybox multi-call fallback**（sh 执行外部命令的关键）：execve 从 guest argv 拷贝参数 → 复用 linux_load_image/linux_build_stack（从 linux_run 提取的公共函数）→ 找不到文件时 fallback 加载 busybox（argv[0] 仍是 applet 名，busybox 按名字分派，等价 Linux busybox symlink）。**不重设 setjmp**（沿用 cmd_linux 的 g_ctx，新进程 exit 仍干净返回）。
- **实测通过（无头 QEMU 256M tcg）**：linuxhello PASS（LINUX_OK）；busybox `echo/uname -a/pwd/id/ls/printf/free(缺procfs)/cat(读VFS)/sh -c id(输出 uid=0 gid=0)/sh -c pwd(/)/sh -c uname(Linux)` 全部执行并干净退出。唯一 unsupported 报错为 whoami 的 /etc/passwd bad record（VFS 记录格式，非 syscall）。
- **测试脚本坑**：QEMU 残留进程锁 bb.img/端口 → 测试脚本 PORT 改为 `4530+pid%200` 随机、LOG 改为 `serial_bb_{pid}.log` 唯一、`-m 256M`；旧 test_linux_compat.py 也改 256M。
