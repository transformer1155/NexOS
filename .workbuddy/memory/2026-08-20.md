## 系统内置 AI 引擎接上 Linux 兼容层 Python 解释器（OS 自己生成并运行代码）

### 目标
让 OS 的 AI 引擎在运行时**生成**一段 Python 源码，并交给 Linux 兼容层里的 freestanding
ELF32 Python 解释器**运行**，做到"OS 自己写程序并跑"。

### 接法（已验证）
- **AI 生成逻辑**：`ai_engine.cpp` 新增 `ai_generate_code(intent,out,outsize)`（extern "C"）。
  是**确定性模板生成器**（按意图关键词 hello/add/fib 选模板），只用解释器支持的语法子集
  （赋值 / print / open / exec / 算术 / 字符串拼接）。**不依赖 GGUF 权重或 Markov 表**，
  故 QEMU(VM) 内零外部资源即可跑。注：`gguf_infer.cpp` 是真 Qwen 推理，但需 .gguf 权重
  （镜像塞不下、当前无权重），VM 下 `ai_env_real_inference()` 返回 0 → 走 Markov/模板。
- **kernel→guest 传代码**：SFS 是**只读**（`vfs.cpp` 写被拒为 read-only backend），不能运行时
  写 `ai_gen.py`。改用 **identity-mapped guest 物理内存**：kernel 把生成代码写到固定空闲地址
  `0x0B800000`（184 MiB，在 64–256MiB PG_USER 区、在 mmap 下限 192MiB 之下、argv 串区
  144MiB 之上，guest 不会碰），再 `linux_run("python",2,{"python","mem:192937984:229"})`。
- **guest 读代码**：`usr/python.c` 的 `read_script` 加 `mem:<addr>:<len>` 协议——前缀匹配后
  直接从该物理地址（guest identity-map，同地址可读）拷贝 len 字节当脚本交给 `run_source`。
  复用已验证的 exec 链路，**guest 零新 ABI**。
- **命令**：`ai py <意图>`（或 `ai code <意图>`）子命令加入 `kernel.cpp` 的 `cmd_ai`，不依赖
  `ai init`。kernel 先 `serial_puts` 回显生成的源码（让用户看到 AI 写了啥），再启动解释器。

### 踩的坑
1. **`ai py` 的 argv 漏了 `mem:` 前缀**：初版 `arg1="192937984:229"`，guest 收到后
   `read_script` 不匹配 `mem:` 分支 → 静默回退内置 demo，且 kernel 回显的源码让 VERDICT 误判
   PASS。修复：kernel 构造 arg1 时先写 `m e m :` 四字节。VERDICT 改为必须命中
   `[python] source: AI-generated code (passed via guest memory)` + `read_script('mem:`。
2. **`linux_run` 实参类型**：签名是 `const char**`，不能传 `(char**)av`（const-drop 非法）。
   `av` 用 `const char* av[3]` 直接传，不要强转。

### 验证
- `tools/verify_ai_codegen.py`（新建）：QEMU pc/512M/tcg → 登录 → `ai py hello world` →
  VERDICT PASS（kernel 回显源码 + python 经 `mem:` 读入并执行 + 干净退出）。
- 回归 `tools/verify_python_hello.py` 仍 PASS（原 `hello_demo.py` 文件路径不受影响）。
- 证据：`build/serial_ai_codegen.txt`、`build/serial_python_hello.txt`。

### 产物
- `ai_engine.cpp`：`ai_generate_code` + 本地 `ai_code_has`（大小写不敏感子串）。
- `usr/python.c`：`g_mem_script[16384]` + `mem:` 协议；`main` 标注 AI 生成来源。
- `kernel.cpp`：`cmd_ai` 的 `py`/`code` 子命令。
- `tools/verify_ai_codegen.py`：新验证脚本。

## 真 AI 推理框架 + 知识库（动态、规则驱动）

### 需求（用户原话）
"真 ai 推理框架并且加入知识库，知识库的原则是真理来源于实践，如果不行的话就去网上
查资料需要查至少三篇都提到这个观点才能进入"

### 知识库原则（落地为规则）
- 一条主张 `kb add` 后为 **CANDIDATE**（未验证）。
- `kb prove #N pass`（实践成功）→ 立即 **ACCEPTED**（真理来源于实践）。
- `kb cite #N <src> <excerpt>` 记录一条**宿主代搜**的网络来源（VM 无外网，检索由 agent/宿主
  执行后注入）。同一主张累计 **≥3 条不同来源**都提到该观点 → **ACCEPTED**（web 佐证）。
- **<3 条** → 保持 CANDIDATE（未成知识，门槛生效）。
- 关键常量 `KB_WEB_MIN = 3`（kb.h）。

### 实现
- **`kb.h` + `kb.cpp`**（新建，32 位 freestanding，同时编译 `kb64.o` 链进 kernel64）：
  固定数组 48 条；`kb_add/kb_prove/kb_cite/kb_query/kb_list/kb_info/kb_init`；
  检索用 **2 字窗口子串匹配**（兼容中文无空格 + 英文），只对 ACCEPTED 事实检索（RAG）。
  `kb_count` 改名 `kb_fact_count` 以避免与 64 位 `knowledge_base.c` 的符号冲突。
- **种子事实（kb_init，幂等）**：
  - #1 NexOS 自研操作系统 → ACCEPTED / **practice**（我们亲手构建并跑通）。
  - #2 规律运动降低心血管风险 → ACCEPTED / **web**，附 **3 条真实权威来源**
    （AHA/Circulation、WHO Guidelines、NHLBI）来自实时 WebSearch，忠实体现"≥3 篇"。
- **`ai_engine.cpp` 新增 `ai_reason(prompt)`**（extern "C"）：RAG 推理框架——
  先 `kb_query` 取一条受信事实注入上下文（"真理来源"接地），再跑**最佳后端生成**
  （VM 内 Markov、裸金属 mini-GPT 前向、64 位可接 GGUF）。命令 `ai reason <prompt>`
  / `ai infer <prompt>`。
- **`kernel.cpp`**：`#include "kb.h"` + `extern ai_reason`；新增 `cmd_kb`
  （add/prove/cite/list/query/info，基于整数 id #N 解析，输出同时镜像 serial 便于验证）；
  命令分发加 `kb`；`cmd_ai` 加 `reason`/`infer` 子命令并自动 `ai_init`。
- **Makefile**：加 `kb.o`/`kb64.o` 编译规则，链入 `kernel.elf`/`kernel_textboot.elf`/`kernel64.elf`
  的 obj 列表。

### 验证（QEMU pc/512M/tcg，os_textboot.img）
- `tools/verify_kb.py`（新建）：登录 → 跑完整规则链 → 断言。
- **PASS**（serial 实测）：
  - #3 `water helps kidneys` `prove pass` → ACCEPTED（practice）
  - #4 `coffee extends lifespan` 第1/2次 cite→CANDIDATE，第3次 cite→ACCEPTED（≥3 web）
  - #5 `moon made of cheese` 1 次 cite → CANDIDATE（门槛生效）
  - `ai reason what is nexos` / `ai reason does regular exercise lower cardiovascular risk`
    → 均 `[RAG] 命中知识库`（分别命中 #1 practice、#2 web×3）
- 证据：`build/serial_kb.txt`。
- 注意：VM 内生成走 Markov（轻量引擎）；真 transformer 前向在裸金属、GGUF 在 64 位需权重。
  kernel_textboot.bin 已 518376 字节（>90% 的 512KiB 加载窗），再加功能要警惕越界。

### 诚实边界
"真 AI 推理框架"= 统一后端选择 + KB-RAG + 生成闭环（真前向推理在 ai_engine.cpp/gguf_infer.cpp）；
但 QEMU(VM) 默认生成后端是 Markov，真实大模型权重当前未载入。网络检索由宿主代做（VM 无外网）。

## 64 位启动内存布局重构（#399）与 UEFI 高帧缓冲验证（#396/#397/#398）

### 问题
