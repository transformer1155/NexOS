## Stage 3：Linux mmap PROT_EXEC + mprotect + 扩大竞技场（NexOS Linux 兼容层）

**目标**：mmap 返回真实可执行匿名页、mprotect 改权限、munmap 回收、竞技场扩大。

**关键架构事实**（本轮确认）：
- 32 位**非 PAE**，4MiB PSE identity-map `0x04000000–0x10000000`（64–256MiB）为 `PG_USER`，**无 NX 位 → 用户页天然可执行**；所以 mmap 页只要真实映射即可执行代码，PROT_EXEC 是语义记录。
- guest 与内核都在 RING 0，#PF handler 无法区分 guest/kernel 故障 → **PROT_NONE 写保护触发 SIGSEGV 的注入本轮未做**（高风险，单列为后续）。
- `vmm_map_page`(kernel.cpp) 原是 `static`，且会自动 split PSE；本轮改为 `extern "C" int` 导出，`vmm_get_phys` 同样改为 `extern "C" uint32_t` 并在 `kernel/vmm.h` 补声明，供 linux_compat.cpp 跨 TU 调用真实建页/查物理页。

**改动**（`linux_compat.cpp`）：
1. 新增 `linux_mmap_region[24]` 区间表 + `linux_mmap_apply_prot`(按 prot 调 `vmm_map_page`+`pmm_alloc_page` 建真实 4KiB 页并零填充) + `linux_mmap_find` + `linux_mmap_reset`。
2. `case 90`(old_mmap)/`case 192`(mmap2)：MAP_ANON 时从 arena 向下分配、登记区间、真实建页；MAP_FIXED 同理。
3. `case 91`(munmap)：查区间、逐 4KiB `vmm_get_phys`+`pmm_free_page`+`vmm_map_page(0,p,0)` 清 PTE。
4. 新增 `case 125`(mprotect)：查区间、改 prot、重设页表 RW 位。
5. 竞技场重排：guest 栈顶 `0x0E000000→0x0C000000`，arena `MMAP_FLOOR=0x0C100000`、`g_mmap_cursor=0x0FFFF000`（栈上方 ~63MiB，无重叠）。`linux_run` 与 execve 路径同步 `linux_mmap_reset()`。
6. 页表 flag 本地定义 `LX_PG_PRESENT/RW/USER`（避免与 kernel.cpp 的 `constexpr` 冲突）。

**验证程序** `usr/linux_mmap.c`（freestanding ELF32，链接 libc.o 的 `_Z6_startv`，拷 `.elf` 进 `linux_root/`）：
- A: mmap PROT_RWX → 写 `mov eax,0x1234;ret` → 调用返回 0x1234（证明可执行页）。
- B: mmap RW → 写 0xDEADBEEF ↔ mprotect(PROT_READ)↔(RWX) 往返 → 数据保留、返回 0。
- C: munmap 返回 0 + 重新 mmap 可用。
- D: 单次 4MiB mmap（VA 0x0FBFB000）全程可写。

**构建/运行**：
- 编译：`i686-elf-g++ -m32 -ffreestanding -nostdlib -fno-builtin -fno-exceptions -fno-rtti -isystem $INC -Iusr -c` libc.c/linux_mmap.c，链接 `-Ttext 0x08048000 -e _Z6_startv`，**必须拷 `.elf`（含 ELF 头）** 进 `linux_root/`（linux_run 解析 ELF）。
- `tools/build_win.sh textboot` → `python tools/verify_linux_mmap.py`：**VERIFY RESULT: PASS (10/10)**。
- Stage 2 信号测试回归：`python tools/verify_linux_signal.py` 仍 PASS（栈顶/arena 改动无回归）。

**留待后续**：PROT_NONE/写保护触 SIGSEGV（需 #PF→guest 信号注入，因 RING0 难区分 guest/kernel 故障，单独排期）；按需求可加 mmap 边界检查/重叠检测与更细粒度 per-page prot 表。

## X-stage 验证链打通：64 位 blit 窗口 bug 根因 + 修复 + 验证 PASS

## Stage 6 — 内核内 ELF 动态链接器 + libc.so（DONE / PASS，9/9）

**目标**：让 freestanding ELF32 guest 通过动态链接调用共享库 `libc.so` 导出的 `printf`/`nex_add`（路线第一片：动态链接 + 最小 libc.so → 后续 musl → JVM 引导桩 → Mesa/3D GL → LWJGL + 真·MC）。

**结构改动**：
- `usr/libc.h`：加 `int nex_add(int a,int b);`（跨 .so 导出测试）。
- `usr/libc.c`：重写为 wrapper —— `#include "libc_impl.c"` + hidden naked `_start`（避免 libc.so 链接时 `main` 未定义冲突）；`nex_add` 实现留在此 wrapper。
- `usr/libc_impl.c`（新建）：全部实现（syscall 包装/socket bridge/heap/string/memory/stdio），无 `_start`；供静态 guest（经 libc.c include）与 libc.so（`-fPIC` 编译）共用。
- `usr/dynlink_crt.c`（新建）：动态链接 guest 的 `_start`（naked，读 argc/argv/envp 调 main）。
- `usr/linux_dynlink.c`（新建）：测试 guest，`main` 调 `printf` + `nex_add(2,3)`/`nex_add(10,20)`，打 `LXDL:` 标记。
- `linux_compat.cpp`：注入完整内核内 ELF 动态链接器（`linux_dynload_and_exec` + `dyn_map_image`/`dyn_parse`/`dyn_resolve`/`dyn_apply_one`/`dyn_apply` + `dyn_mod_t`/`DYN_LIB_BASE=0x0A400000`/`DYN_MAX_LIBS=8`）；`linux_build_stack` 加 `at_base`(AT_BASE) 形参；两处静态调用点补 `,0`；`linux_run`/`sys_execve` 重执行路径接入 `linux_dynload_and_exec`（`dr==1` 走静态路径，`dr<0` return -1，`dr==0` unreachable）。
- `Makefile`：`libc.so` 规则（`-fPIC -fno-plt -c libc_impl.c` → `i686-elf-ld -m elf_i386 -shared -nostdlib --soname=libc.so --hash-style=sysv -z now`）；`linux_dynlink` 规则（两 .o 显式 `-x c -m32 -ffreestanding -nostdlib -fno-stack-protector -fno-asynchronous-unwind-tables -O2 -Wall -Wextra -Iusr -fPIE -fno-plt -c`；链接 `i686-elf-ld -m elf_i386 -nostdlib -e _start --no-dynamic-linker -pie -L$(LINUX_ROOT) -lc`）；`$(LINUX_SFS_IMG)` 依赖恢复 `linux_dynlink`（之前因 stage-6 链接重叠临时移除，已修好）。
- `tools/verify_linux_dynlink.py`（新建）：无头 QEMU harness（pc/256M/tcg，无 NIC），登录 root/admin→等 Shell→`linux linux_dynlink`→抓 serial 9 项 CHECKS。

**关键架构事实（交接必读）**：
- 无 `PT_INTERP`/ld-linux，内核自身当链接器；映射主程序 + `DT_NEEDED` 的 `.so`，应用 `R_386_RELATIVE/GLOB_DAT/JMP_SLOT/32/PC32`，设 `AT_BASE`，跳主程序 entry。
- 主程序编 PIE（`-fPIE -pie`），内核算 `main_bias = 0x08048000 - (first_v - first_o)` 使其落入 0x08048000 区；`mods[0].base = main_bias`，RELATIVE `+=base`。
- `.so` 加载基址 `DYN_LIB_BASE=0x0A400000`（字符串区 0x09000000 之上、栈顶 0x0C000000 之下）。
- **PIE 入口/AT_ENTRY 必须 +main_bias**：运行时 entry = `entry + main_bias`，否则跳裸链接地址 0x1D0 → #PF（本阶段已踩，已修）。
- `dyn_apply(lib, mods, nmods+1)` 必须含 lib 自身，否则 libc.so 内部 GLOB_DAT（printf→vprintf→nex_write）解析失败刷大量 `dyn: unresolved`。
- `i686-elf-ld` 的 `--soname=` 用**等号**（`--soname=libc.so`），逗号形式（`--soname,libc.so`）被拒。

**验证（无头 QEMU tcg `-m 256`）**：9/9 PASS —— `dyn: loaded libc.so at 0x0A400000` / `dyn: transferring control` / `LXDL: printf_ok` / `LXDL: resolved_sym_ok` / `nex_add(2,3)=5` / `nex_add(10,20)=30` / 无 unresolved / 无 dyn error / `linux: process exited`。落盘 `build/serial_linux_dynlink.txt`。

**待后续（路线下一片，用户授权但本次未做）**：musl 适配（替换手写 libc.so，提供完整 libc API 给 JVM）；JVM/Hotspot 引导桩（解释 ELF + 设置 JNI/GC 堆）；Mesa/3D GL；LWJGL + 真·MC Java 版。
