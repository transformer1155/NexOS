## NE2000 网络栈修复（2026-08-10 收尾）

目标：64 位 MiniOS 浏览器经 QEMU `-netdev user` + NE2K-ISA 访问 host 服务器 `http://10.0.2.2:8137/` 并显示完整网页。

修复要点（都在 `net.cpp`）：
1. **统一 IPv4 常量字节序**：全部使用 `IPV4(a,b,c,d) = a<<24|b<<16|c<<8|d`（可读大端序），`our_ip/gateway/DNS_SERVER` 分别改为 `IPV4(10,0,2,15)`/`IPV4(10,0,2,2)`/`IPV4(10,0,2,3)`。之前写成 memory-byte-order 形式（如 `0x0F02000A`）会让线路上出现 `15.2.0.10`，SLIRP 完全不回包。该约定已在源码顶部以整段注释固化，并新增 `IPV4` 宏防止再犯。
2. **子网掩码修正**：`10.0.2.0/24` 判断由 `(dst_ip & 0x00FFFFFF)` 改为 `(dst_ip & 0xFFFFFF00)`，与新 IP 表示法匹配。
3. **`arp_lookup` / `handle_arp` 字节序补漏**：缓存表统一存 host-order；对 `op==2` 的 ARP reply 的 `sender_ip` 加 `ntohl()`；直接 IP 解析 `tcp_client_connect()` 改用 `IPV4()`。`net_serial_ip()` 的打印顺序也改成高字节优先。
4. **`nic_receive()` 空环判断修复**：原 `if (curr == bnry) return 0` 永远不为真（init 中 `CURR=RX_START+1`、`BNRY=RX_START`），导致每轮远程 DMA 垃圾头。改为 `hdr_page = bnry+1` 后 `if (curr == hdr_page) return 0`。
5. **IP `flags_frag` 字节序**：`0x4000` 是内存小端字，写入会发出 `00 40`（被当成分片 offset=64）；改为 `htons(0x4000)` 发出 `40 00` 的 DF 位。
6. **TCP 校验和字节序**：伪头部中 `0x0006` 和 `len` 要按“小端字域”累加；改为 `0x0600` 和 `htons(len)`，SYN 校验和正确，SLIRP 立即回 SYN-ACK。
7. **ICMP / server-side TCP 路径的 `ip->src_ip` 加 `ntohl()`**：`handle_icmp` 回包、`tcp_find`/`tcp_alloc` 不再拿 wire-order 的 IP 当 host-order 比较。

用户原话："把64位的功能和32位的同步一下…登录功能权限系统"。P2(登录)+P3(权限) 代码上轮已移植进 `.attic64/kernel64.cpp`（kmain64 在进 shell 前 `perm_init`→`userdb_load`→`seed_default_users`→`permdb_load`→`login_prompt`；run_command 分发 whoami/id/users/login/logout/su/useradd/deluser/passwd/chmod/stat/sudo/perm；读/删文件接 `perm_check`；consent 引擎 `perm_ui_console` 接线）。本轮做构建修复 + 真机验证。

### 32 位 `kernel.elf` 链接 `__udivdi3` 未定义（仓库既有缺陷，已修）
- 根因：`gguf.cpp`(`ai_gguf_type_size`) 用 64 位 `/` 与 `%`，freestanding `-m32 -nostdlib` 下编译器生成 `__udivdi3/__umoddi3/__divdi3/__moddi3`，但环境**无 i386 multilib libgcc**（路径不存在），链接失败。
- 修复：新建 `divdi3.c` 提供这四个 helper（shift-and-subtract）。
- **关键 gotcha（勿再踩）**：`Makefile` 里 `CC = g++`！`g++` 把 `.c` 文件**当 C++ 编译**，导致符号被 name-mangle 成 `_Z9__udivdi3yy`，`ld` 仍报 undefined。必须给 `divdi3.c` 加 `extern "C" { ... }` 包裹导出纯 C 符号（兼容 C/C++ 两种编译路径）。
- 已接入 `Makefile`：新增 `$(BUILD)/divdi3.o` 编译规则，并把 `divdi3.o` 加进 `kernel.elf` 的依赖与 `$(LD)` 链接行。`make build/os.img` 全量通过。

### 测试时序 race（导致上轮 `test_login64.py` 假阴性）
- 现象：serial 全程只有 32 位 `[SHELL] $`，无 `[K64-1]`/`[K64-LOGIN]`，`switch64` 根本没切过去。
- 根因：测试用固定 `sleep` 等启动；QEMU 启动慢时，初始 `root`/`admin` 在 32 位登录提示符就绪前被吞，连带 `switch64` 被登录提示符消费，整轮都跑在 32 位 shell。
- 64 位内核本身正常铁证：`kmain64` 一进就打 `[K64-1] kmain64 entered`（kernel64.cpp:4770），失败日志里没有它 → 纯测试时序问题，非内核/串口 bug。
- 修复：`tools/test_login64.py` 改为**轮询串口标记**等就绪，而非固定 sleep：`[SHELL] $`(32位 shell 就绪) → `switch64` → 等 `[K64-1]`(确认切入) → 等 `[K64-LOGIN] OK user=root`(64位登录)；登录失败带 retry 循环。
