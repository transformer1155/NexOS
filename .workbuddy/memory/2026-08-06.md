## Wine-on-MiniOS：linux_compat 层 (Milestone 0) — 跑通真实 Linux ELF
- 用户最终决定：**直接用 Wine**，适配我们写的内核 → 内核需提供 Wine 的 Linux 后端所依赖的宿主 ABI（`int 0x80` 系统调用分派 + ELF 加载器）。这是 Milestone 0：Linux 二进制兼容 shim，guest 跑在 ring 0（隔离留待后续里程碑）。
- 新增文件：`linux_compat.cpp` / `linux_compat.h`（内核侧 shim）、`tools/linuxhello.S`（测试 ELF 源，`as --32` + `ld -m elf_i386 -static -Ttext=0x01400000` 构建，拷到 `sfs_files/` 由 Makefile 打进 SFS）、`tools/test_linux_compat.py`（无头 QEMU 测试，断言 `LINUX_OK` 且 `RESULT: PASS`）。`kernel.cpp` 在 `idt_init()` 里 `idt_set_gate(0x80,...,0x08,0xEE)` 接 `linux_syscall_entry`，并注册 SFS reader + `linux` 命令。
- **两个已修根因（勿再踩）**：
  1. **SysRegs 结构体顺序 vs 汇编 push 顺序不匹配 → 读到的全是错寄存器**：原 asm 先 `push %eax`...后 `push %ebp`，栈向下生长，最低地址(结构体 offset 0) 实际是 ebp，导致 `r->eax` 读到 ebp（陷阱里恒显 `[sc 2]`，`LINUX_OK` 从不打印）。**修正**：push 顺序改为 `ebp,edi,esi,edx,ecx,ebx,eax`，使最后入栈的 eax 落在 offset 0，匹配 `struct {eax,ebx,ecx,edx,esi,edi,ebp}`。可用 `objdump -d` 核对 `linux_syscall_entry` 的 push 顺序确认。
  2. **guest 退出路径极度脆弱（布局相关）**：最初 `push %[ret]; ...; ret` 与后来 `&&ret_label` + `jmp g_ret_addr` 在 `-O2` 下都靠不住——`ret_label` 同时被两条路径到达（正常落穿 vs sys_exit 的 jmp），落穿路径建立的寄存器在 jmp 路径下是垃圾，导致行为随代码布局变化（有调试打印时正常、无时乱跳/二次执行）。中间还试过 C 函数版 `mini_setjmp`/`mini_longjmp`，但因 gcc 自动加 prologue，`0(%esp)` 不再是回到 `linux_run` 的返回地址 → `c->eip` 抓错 → 二次执行且 "process exited" 不打印。
  3. **最终稳健方案 = naked setjmp/longjmp**：`mini_setjmp`/`mini_longjmp` 用 `__attribute__((naked))` 纯汇编函数，自己掌控 prologue/epilogue；`Ctx{ebp,ebx,esi,edi,esp,eip}` 偏移 0/4/8/12/16/20。setjmp 从 `%esp` 直接抓返回地址（裸函数入口处 `%esp` 即指向返回地址），longjmp 恢复寄存器+esp 后 `ret` 回到 `linux_run` 的 `if(mini_setjmp()!=0)` 分支（eax=1），由 else 分支 `return g_linux_exit_code`，干净回到 `cmd_linux`。**注意**：naked 函数内是 basic asm，寄存器写 `%eax`（单 `%`），不是 extended asm 的 `%%eax`；且不能含 C 语句（如 `(void)x;`）。
- **验证结果**：`wsl -e bash -lc 'cd /mnt/d/MyOS/bootloader && make build/os.img && python3 tools/test_linux_compat.py'` → `[sc 4]LINUX_OK[sc 1]linux: process exited` + `RESULT: PASS`，多次运行稳定单次执行（sc4 计数=1，process-exited 计数=1），无 EXCEPTION。
- **测试环境注意**：本机 Windows 无 `qemu-system-x86_64`（PATH 里没有），测试脚本里直接 `subprocess.Popen(["qemu-system-x86_64",...])` 会 FileNotFoundError。必须 **在 WSL 内跑该测试**（WSL 有 qemu 10.x，TCG 无 KVM 也能无头跑），相对路径 `build/os.img` 在 WSL 下指向 `/mnt/d/MyOS/bootloader/build/os.img`。连续跑需先 `pkill -f qemu` 释放 4451 端口，否则 BrokenPipe。

### VFS 设计（vfs.cpp）
- **命名空间模型**：全局单树 `/apps/<app>`、`/system`；每个 Process 的 `root_path` 就是沙盒边界。
  相对路径 → 拼到 root_path 后面；绝对路径 → 按字面取，然后做包含性检查；`..` 在检查**之前**折叠，所以 `../../system/passwd` 归一化成 `/system/passwd` 后照样被拒。
- **后端**：SFS 是**扁平 20 字符命名空间、无目录**，所以虚拟路径映射到物理时取 basename。安全判定发生在完整虚拟路径上——这才是沙盒关心的部分。给 SFS 加真目录是另一件正交的事。
- **唯一收口点 `vfs_check_access(abspath, mode)`**：ring 0 或 uid==SYSTEM_UID → BYPASS（打审计日志）；不在 root 下 → DENIED；写 → DENIED（只读介质）；否则 GRANTED。文档里的 Y/N 弹窗(3.3)、签名信任(3.4)、伪信息引擎(3.6) 后面全插这一个函数。
- fd 表 8 项，0/1/2 保留给标准流，用户 fd 从 3 起；每 fd 带 2KB payload cache（open 时整文件读入）。
- `vfs_init(read_fn, size_fn)` 由 `kernel.cpp` 的 `kmain` 注入 SFS 后端（和 `linux_compat_init` 同一套路）。

### 修掉一个隐藏很深的 bug：syscall 返回值从来没送回 guest
`sys_enter`（以及 `linux_compat.cpp` 的 `linux_syscall_entry`）尾声是 `addl $32,%esp; iret`——**把保存的寄存器块直接丢弃，从不回写**。于是 ring-3 拿到的 `eax` 其实是 `movl %esp,%eax` 留下的内核栈指针垃圾值。
之所以一直没暴露：此前的 guest（`linuxhello`、第一版 `userdemo`）只做 write()+exit()，从不检查返回值。VFS 需要真 fd 和负 errno，必须修。
**正确尾声**（栈平衡已验算：入口 esp0-20 是 CPU 压的 5 dword iret frame，7 次 push 到 esp0-48，push 参数到 esp0-52，`addl $4` 回 esp0-48，7 次 pop 回 esp0-20 正好指向 iret frame）：
```
    addl $4, %esp      ; 丢掉 SysRegs* 参数
    popl %eax          ; <- 返回值真正到达 guest
    popl %ebx / %ecx / %edx / %esi / %edi / %ebp
    iret
```
- 用户指针校验：`user_range_ok()` / `user_str_ok()` 检查 ring-3 传来的指针必须落在 `USER_BASE..USER_END`，否则返回 -EFAULT。防 confused deputy（guest 递内核地址让内核替它读写自己）。

### kernel.cpp 改动
- `vmm_init()` 尾部加 PG_USER 区：`for(i=0x10;i<0x20;i++) page_directory[i] = i*0x400000 | PG_PRESENT|PG_RW|PG_USER|PG_PSE;` → 身份映射 64–128MiB 给 ring 3。
- `kmain` 里 `gdt_init()` 排在 `idt_init()` 之前；`vfs_init(...)` 紧跟 `linux_compat_init(...)`。
- 新命令 `user`（加载 `userdemo` 到 USER_BASE，`proc_spawn("userdemo",1000,"/apps/userdemo")`，`enter_user`）和 `vfs <path>`（以内核身份 resolve+open+read，演示 SYSTEM 旁路）。
- **坑**：`cmd_vfs` 一开始只用 `term.write()`，那是写 VGA 终端**不进 serial 日志**，无头测试断言全落空。凡是要被测试断言的输出必须 `serial_puts()`。
