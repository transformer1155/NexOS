## SSH-2 服务器 AES/CTR 解密 bug 修复（net.cpp + test_ssh.py）

### 根因（两处独立 bug，缺一不可通过 test_ssh.py）
1. **AES-128 字节布局错（行主 vs 列主）**：原 `aes_enc_block` 用行主状态，但 FIPS-197 / SSH 标准（及 test_ssh.py 客户端）用**列主**（字节 i = row(i%4) + col(i//4)）。HMAC 因只验密文+key 不依赖 IV 而「假通过」，解密却全错。重写 `aes_enc_block` 为列主（shift 用 `t[r+4*c]=s[r+4*((c+r)&3)]`、mix 用 `s[4*c..4*c+3]`），与客户端一致。已用 FIPS 向量 `69c4e0d8...` 验证（另写 tools/_aes_c_test.c 独立 C 测试，已删）。
2. **CTR 解密偏移错位（padlen 字节）**：自定义 SSH 线格式为 `length(4,明文) || ct(pktlen= AES-CTR[padlen(1)+payload+padding])`——即 padlen 字节加密藏在 ct[0]。原 `ssh_try_parse` 误把 `s->pb[4]` 当明文 padlen 读、且从 `s->pb+5` 解密（跳过 ct[0]），导致 keystream 整体偏移 1。修正：解密 `s->pb+4` 共 pktlen 字节（原地），`padlen=s->pb[4]`（解密后），IV 推进 pktlen 字节。test_ssh.py 的 `read_packet` 收包侧有**完全相同**的 off-by-one，一并修正为解密 `raw[4:]`、`padding=dec[0]`。

### 其他清理
- 删 net.cpp 内临时诊断打印（mac_calc/mac_recv/macin/cseq/dec/H/c2s_key/f/K/e/K1-K4 等 net_serial 标记）；test_ssh.py 删 `[SSH-CLIENT]` 调试打印。
- `ssh_kex_reply` 密钥派生去掉被 [4]/[5] 覆盖的死赋值 [2]/[3]。
- 保留 `ssh_try_parse` 内一行 `[SSH] dec padlen=` 精简状态标记（调试有用）。

### 验证
- 重建 `build/kernel.bin` + `build/os.img`（MSYS2 bash + i686-elf-g++）。
- `python tools/test_ssh.py` → **SSH TEST PASSED**：banner→KEX(dh-group14-sha1)→password auth(root/admin)→`exec 'echo hello-from-ssh'` 回显 `hello-from-ssh`→`exec 'ver'` 返回 30 字节。多包 c2s/s2c 方向 CTR IV 连续推进正确（iv 每包 +2）。

### 备注
- 自定义线格式（padlen 加密进 ct[0]）非标准 SSH，仅为与自研客户端一致；将来若要兼容 OpenSSH/PuTTY 需改成标准（length 也加密 + 解密先解首块取 pktlen）。
- 构建/验证纪律同前：纯 Windows MSYS2，无头 QEMU `-m 256M -accel tcg,tb-size=128`，hostfwd tcp::18042-:22。

## Stage 1 第一刀：Linux 兼容层线程支持（clone/futex/TLS + 协作调度）

### 背景
远期目标：扩展 Linux 兼容层以跑真·《我的世界》Java 版。路线拆 8 阶段，阶段1 = 线程支持。本次落地第一刀。

### 关键发现（内核既有缺陷）
- `int 0x80` 陷阱入口（`linux_syscall_entry` 裸 asm）在 `call linux_syscall_dispatch` 之后、`add esp,32; iret` 之前**没有**把 `r->eax`(返回值) 装回 eax，导致系统调用返回值丢失（clone 父拿不到子 tid）、线程切换后寄存器不一致。→ 入口加 `movl 4(%esp),%eax; movl 0(%eax),%eax;`。
- `gdt_set_tls` 写单槽 `g_gdt.tls`(0x38) 却 `return 7`(0x3B)，slot 号 bug，且单槽无法满足每线程 TLS。→ 旁路：sys_set_thread_area 改用新 `gdt_alloc_tls`。

### 内核改动
- **gdt.cpp**：`GdtTable` 加 `tls_pool[16]`(0x40..0xB8)；新增 `gdt_alloc_tls(base,limit)`(返回 0x40+i*8) / `gdt_free_tls(selector)`；`g_tls_used[16]` 跟踪。
- **linux_compat.cpp**：
  - 加 `linux_thread[16]` + `g_cur/g_live_threads/g_next_tid` + `linux_futex_q[32]`。
  - 裸 asm `linux_switch_asm(next_esp, next_gs)`：切 gs、esp，弹 6 寄存器，add esp,32，iret（上下文切换只保存「指向 EIP 的 esp」`r+28` 并 iret）。
  - `linux_do_switch`(协作轮转)、`linux_futex_park`、线程级 `sys_linux_exit_thread`、`sys_linux_exit_group`。
  - dispatch 新增：`case 120` sys_clone(NexOS ABI: ebx=child_entry, ecx=child_stack TOP, edx=flags, esi=arg, ebp=tls_base; CLONE_SETTLS=0x20000→gdt_alloc_tls; 合成子线程陷阱帧 eax=0,eip=child_entry,cs=0x08,eflags=父帧; 父返回子 tid)、`case 158` sched_yield、`case 224` gettid、`case 240` futex(WAIT=0/WAKE=1)。
  - `case 1` sys_exit → exit_thread；`case 252` sys_exit_group → exit_group；`case 243` sys_set_thread_area → gdt_alloc_tls 每线程。
  - `linux_run` 重置块初始化 TCB。
- **usr/linux_threads.c**（新建）：raw 系统调用 4 线程共享计数器 PER_THREAD=50000、barrier、futex WAKE、main sched_yield join；断言 `counter==200000`。
- **tools/verify_linux_threads.py**（新建）：无头 QEMU 登录 root/admin、跑 `linux linux_threads`、抓串口断言 `LXTHREADS: PASS` + `counter=200000`。

- 无本机 C 编译器（MSYS2 无 gcc、无 VS、TCC/OVMF 下载均被 sandbox 网络拦截），故无法在宿主侧编译 font_vec 单元测试验证 stb 光栅化。

### 结论

## Stage 2：Linux 信号投递（signal / tkill / tgkill / rt_sigreturn 最小集）

### 背景
远期路线阶段 2：信号投递。上一会话已修复架构 bug（把 `linux_deliver_signals` 调用从死代码 `linux_syscall_entry` 移到真实入口 `sys_enter`），本会话让验证程序真正 PASS。

### 关键修复（本会话）
1. **SIG_SLOT_GAP 布局修正（handler 返回 #PF 下溢）**：`linux_thread.sig_slot` 扩到 `[160]`；`linux_deliver_signals` 与 `sys_linux_rt_sigreturn` 中虚拟 iret 帧放到 `t->sig_slot + SIG_SLOT_GAP`（`#define SIG_SLOT_GAP 88` 字=352B）。handler 以 `esp=frame+44` 运行向下 push，下方留大面积 scratch，不再下溢缓冲。
2. **clone 不共享信号处理（worker 收不到信号根因）**：`sys_clone`(case 120) 原只建空线程，worker `sa[]`/`blocked` 全 0（SIG_DFL）→ SIGUSR1 默认 ignore 不触发 handler。修正：clone 时从父线程拷贝 `sa[0..LINUX_SIG_MAX]` 与 `blocked`（Linux 语义：信号处理是进程级共享）。
3. **协作调度死锁**：worker 循环无 yield，一旦拿到 CPU 永不归还，main 无法发信号/检查。修正：worker 循环 `sys_gettid()`(信号边界) 后加 `sys_sched_yield()` 归还 main。
4. **测试入口名 mangling**：`usr/libc.c::_start` 用 g++ 编译被 mangle 成 `_Z6_startv`，链接 `-e _start` 解析到 0x08048000（错误代码）导致 "unsupported syscall 150994944"(=0x09000000=STR_BASE，eax 垃圾)。修正：链接用 `-e _Z6_startv`。
5. **测试构建流程**：`usr/linux_signal.c` 需手动编译（Makefile 无目标）：
   ```
   i686-elf-g++ -m32 -ffreestanding -nostdlib -fno-builtin -fno-exceptions -fno-rtti \
     -isystem <elf_tools>/lib/gcc/i686-elf/13.2.0/include -Iusr -c usr/libc.c -o build/ls_libc.o
   i686-elf-g++ ... -c usr/linux_signal.c -o build/ls_signal.o
   i686-elf-g++ -m32 ... -Ttext 0x08048000 -e _Z6_startv build/ls_libc.o build/ls_signal.o -o build/linux_signal.elf
   cp build/linux_signal.elf linux_root/linux_signal   # 必须拷 .elf（含 ELF 头），objcopy -O binary 会剥头 → "not an ELF image"
   ```
   然后 `tools/build_win.sh textboot` 重打包 linux_sfs。

### 验证脚本检查项修正
- `tools/verify_linux_signal.py`：原检查 `"SIGUSR2 blocked, pend set" in out` 因 QEMU 串口字符级交错（handler 在 unblock 边界触发，其 sys_write 与上一条 sys_write 的 UART 缓冲交叉）导致字符串被拆成 "pend se"+"HANDLER..." 而误 FAIL。改为检查 `"FAIL SIGUSR2 delivered while blocked" not in out and "HANDLER main tid=1 sig=12" in out`（handler 输出自身完整不被拆）。
- 同样 "SIGUSR2 delivered after unblock" 改为 `"HANDLER main tid=1 sig=12" in out and "signal tests done" in out`。

### 验证结果（无头 QEMU tcg）
`python tools/verify_linux_signal.py` → **VERIFY RESULT: PASS**（8/8）：
- HANDLER main tid=1 sig=10（tkill 自送 SIGUSR1，handler 正确触发 + 收号 + sigreturn 恢复）

- blocked SIGUSR2 stayed pending（block 期间 tkill 不投递）
- SIGUSR2 delivered after unblock（unblock 边界投递 sig=12）

## Stage 4 — argv/envp 透传（DONE / PASS，8/8）

### 目标
让 `execve`(syscall 11) 的 **envp（r->edx）真正解析并透传** 到新映像，且命令行 argv 能从 `linux <prog> [args]` 到达 guest `main()`。

### 根因修复（真正卡死点）
- Stage 4 实测最初「加载 linux_argv 时 PH 洪泛、静默卡死」。
- **根因**：客户机旧链接基址 `NEX_TEXT=0x01800000`（=0x1800000）与 `linker.ld` 保留的 **32 位内核启动栈 0x1800000–0x1810000** 重叠（`linker.ld` 2026-08-19 把栈从 0x90000 迁到 0x1800000 后，旧基址即成雷）。`linux_load_image` 加载 PH1（`p_vaddr=0x01801CE0, p_memsz=0x40008`）时 bss 清零**覆盖内核栈帧**（循环变量 `i`、`phnum`、返回地址被清零）→ `phnum` 变 0 → `i<phnum` 永假 → 无限循环（serial 铁证：第 3 次起 `[i=1 phnum=0 ...]`）。
- **修复**：`Makefile` `NEX_TEXT := 0x08048000`（落入 64–256MiB PG_USER 空闲区，与 `linux_run` 既有布局注释 ELF@0x08048000 / 栈@0xC000000 / mmap@0xC100000–0x0FFFF000 一致），彻底避开内核栈。`rm -f linux_root/* build/linux_sfs.img` 强制重链重建。
- linux_compat.cpp 仅保留合法 `bad e_phnum` 守卫（`if (phnum==0||phnum>64) return -1;`），临时调试代码已清。

### 验证（无头 QEMU tcg，2026-08-23 复跑 + 本次 fresh 复跑均 8/8 PASS）
`python tools/verify_linux_argv.py` → **GOOD: Stage 4 PASS**：
- 命令行 argv 到达 main：`linux linux_argv hello world` → `argc=3 argv[1]=hello argv[2]=world`
- 默认 envp 可见：`env[PATH=/sbin:/bin:/usr/sbin:/usr/bin]`
- **execve envp(r->edx) 真正透传**：`linux linux_argv spawn` 自举 `sys_execve("/linux_argv", [...,"via_execve"], ["STAGE4=ENV_PASSED","FOO=BAR"])`，新进程 `argv[1]=via_execve` + `env[STAGE4=ENV_PASSED]` + `env[FOO=BAR]`，且 `PATH=(not set)`（证明自定义 envp 精确传入、无默认泄漏）。
- 8 项断言全 PASS：`argc=3` / `argv[1]=hello` / `argv[2]=world` / `默认 envp 可见` / `execve 触发` / `STAGE4=ENV_PASSED` / `FOO=BAR` / `process exited`。
