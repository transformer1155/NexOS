fix: menu freeze without mouse input + permanent cursor ghost (7 patches)

Two related damage-tracking bugs, both rooted in dirty rects that mark
regions the frame never actually rewrote:

Bug 1 -- menu frozen half-drawn until a mouse event:
  osig (overlay signature) could not see managed menu state: the
  start_menu_open flag only tracks the NATIVE fallback, so a C# popup
  changed no osig component. Once g_over_force_n (6 frames = 96ms)
  drained -- shorter than the 150-170ms C# transition -- over_dirty went
  permanently false and gui_tick (render_all only while g_mforms_anim)
  stopped scheduling frames entirely, so even the g_over_idle>=30 safety
  net could never fire. Menu stuck mid-transition.

  Fixes: mix menu_up into osig; OVER_FORCE_FRAMES 6->12 (192ms>170ms);
  2Hz gui_tick keepalive when anim==0; idle fallback 30->2.

Bug 2 -- permanent ghost cursor after long-press / menu hover:
  The cursor block skipped restore_bg when a damage rect fully contained
  the 32x32 cursor box ("under_covered"), trusting that the backbuffer
  under it was rewritten. But the L7715 blanket full-screen flush and the
  BUG-C1 window rects are present-only markers: overlay/BUG-C1 frames
  never rewrote the desktop pixels there. save_bg() then baked the
  previous frame's cursor pixels into the snapshot -> ghost forever.

  Fix: replace the damage-walk containment test with a frame-scope flag
  set only in the real desktop-repaint path (bg_repainted_this_frame).

Verified QEMU headless (tools/verify_fixes.sh + verify_diff.py):
  S1 right-click then FREEZE 3s: 47,733 px menu rendered (was 4,109)
  S2 hover over menu: 288 px (hover highlight only, no pollution)
  S3 long-press release: 0 px diff at press point and along whole
     cursor path -- ghost eliminated (was permanent 32x32 residue)
