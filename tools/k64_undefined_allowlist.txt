# ============================================================================
#  k64_undefined_allowlist.txt - symbols the 64-bit kernel links as ZERO
# ----------------------------------------------------------------------------
#  kernel64 links with --unresolved-symbols=ignore-all, so a symbol this build
#  does not define is silently bound to address 0.  Any *call* through one of
#  them jumps to 0, executes the real-mode IVT bytes and ends in #UD -> #GP ->
#  #DF -> triple fault, which the user experiences as a random reboot.
#
#  That is not hypothetical: task-8 lost a whole day to it.  serial_enter /
#  serial_leave were missing, fb_console_init() called one, and the 64-bit
#  kernel rebooted before it ever reached the driver scan.  bigbuf_alloc was
#  the next one -- it killed gui_init() on its first backbuffer allocation.
#
#  tools/check_k64_undefined.sh now fails the build for any symbol that is NOT
#  listed here, so a new missing symbol can never ship silently again.
#
#  THIS FILE IS A BURN-DOWN LIST, not a blessing.  Each entry is a live
#  landmine: delete a line only after the symbol is actually defined (then the
#  check stays green), and prefer deleting lines over adding them.
# ============================================================================
