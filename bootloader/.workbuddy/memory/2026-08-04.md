## mkfs 数据搬到独立数据 VHD (2026-08-04 17:25) ⭐⭐⭐
用户要求：mkfs 数据搬到独立的用户数据 VHD。响应用户在 VirtualBox 里"MyOS.vdi 重启丢失"问题。
### 架构改动
- MiniOS 把 mkfs 数据从启动盘搬到独立 ATA 硬盘
- 启动盘（ISO/软盘）保持只读/不可变；mkfs 写到用户数据 VHD
- VirtualBox/QEMU 双盘配置：启动介质 + 数据 VHD，文件持久化
### 实现 (kernel.cpp)
1. ATA 驱动重构：ata_wait_bsy_base/drq_base (base port 参数); ata_read/write_sector_disk(base, drv, lba, buf) 全功能版; 保留原 ata_read/write_sector (primary master) 给 SFS/CMD_FILE 等用
2. ata_find_hdd(): 遍历 0x1F0/0x170 × master/slave, IDENTIFY DEVICE 找第一个 ATA 硬盘（排除 ATAPI CD-ROM 用 word0 bit15）
3. fs_* 抽象：g_fs_base/g_fs_drv/g_fs_is_data_disk; fs_read_sector/fs_write_sector 用当前设备
4. Mkfs::init: 先 ata_find_hdd 设 g_fs_base/drv, 再 fs_read_sector 读 MKFS super
5. Mkfs::format: data disk 用 DATA_DISK_SECTORS=15200 (~7.5MB), boot disk 用 MKFS_DATA_SECTORS=271
6. create() 检查越界: `MKFS_DATA_LBA + sb.total_sectors` (动态)
7. Mkfs 类外 7 处 MKFS_TABLE_LBA 操作 (tab/chmod/stat/GUI) 改走 fs_*
### 工具
- tools/make_data_vhd.py: 生成 build/data.vhd (8MB raw 预格式化 MKFS)
- Makefile: data-vhd, iso-run-data 目标 (-cdrom os.iso -boot d -m 2G -drive data.vhd,index=1)
### 关键 bug
- ata_find_hdd 只读 1 word IDENTIFY, 设备 DRQ 仍置位 → 后续 READ 读残留数据
- 修复: 读满 256 words 清 DRQ + 用 word0 bit15 精确排除 ATAPI CD-ROM
### 实测 (QEMU iso-run-data)
✅ BOOT1 serial: "[MKFS] Data disk: ATA primary slave" + "[MKFS] Mounted, data area (user data disk)"
✅ BOOT1 screenshot: mkdir myfolder + touch hello.txt → ls 显示 shadow/permdb/myfolder/hello.txt
✅ BOOT2 serial: MKFS mounted (4 files) (重启后跨启动读到 4 个文件)
✅ BOOT2 screenshot: ls 显示所有 4 个文件持久化成功
### VirtualBox 配置 (用户场景匹配)

## GUI 真正修复：BGA ports fallback (2026-08-04 19:16) ⭐⭐⭐⭐
用户问"为啥 GUI 不行"——这是他 VirtualBox 里实际跑的 BIOS 路径截图：64MiB RAM, "GUI not available (VBE graphics mode not set)".
### 真正的根因（找到之前的误判）
- QEMU SeaBIOS 默认 Cirrus VGA + VMSVGA + VirtualBox VBoxVGA 都可能没有经典 VBE BIOS
- stage2 在 32-bit PM 下 INT 10h 0x4F00 (VBE query) 失败 → 0x5400 全 0 → 0x500D (vbe_ok) = 0
- kernel 检测 `*vbe_flag == 1` 失败 → g_vbe_active=false → cmd_gui 拒绝
- 但 **BGA ports (0x1CE/0x1CF) 是 QEMU/VirtualBox/Bochs 都提供的标准接口**——之前没用上！
### 修复 (gui.cpp + kernel.cpp)
1. gui_probe_vbe() (extern "C"): 检查 `info->vbe_ok==1`（BIOS/UEFI 已写）；若否则 `bga_detect()` (读 0x1CE/0x1CF ID 0xB0C0-0xB0C6)；BGA 可用则**合成 VBE info** 写到 0x5000: width=1024 height=768 bpp=32 BGRX32 mode=0x117 LFB=0xE0000000
2. Graphics::init 保留同样 fallback: bga_detect 成功则合成 VBE info 后继续 init
3. kernel.cpp kmain: 在 detect_hardware 后 (vbe_flag 检查前) 调 `gui_probe_vbe()` → 写 0x500D=1 → kernel 检测 `*vbe_flag==1` 成功 → g_vbe_active=true
4. cmd_gui: 把 `gui_available()` 检查改为 `gui_init()` (按需 init, heap 已就绪)
5. enter_gui: 已有 force_clear_lfb() 清残留
### 实测 (QEMU -cdrom -boot d -m 64M, SeaBIOS+Cirrus)
✅ serial 完整流程:

  [GUI] Allocated shadow framebuffer at low address  ← shadow 在 RAM 内
  [GUI] Framebuffer initialized with double-buffering
  [K32] Entering Win11 GUI mode
  [GUI] VBE mode set via BGA ports  ← BGA 真正设 VBE 模式
  [GUI] Entered GUI mode
✅ framebuffer 切到 1024x768 32-bit

## 壁纸/桌面渲染修复完成 (2026-08-04 19:30) ⭐⭐⭐
GUI 进去了但全黑屏（之前 BGA fallback 修复后）。三处串联 bug 导致黑屏，全部修复。
### Bug 1: fill_gradient 用了 float
- `float t = row/h; (1-t)*color` 在 freestanding 32-bit kernel 里 float 运算可能软浮点 helper 缺失或 FPU 未启用
- 修复: 改纯整数插值 `r = tr + (br-tr)*row/h`
### Bug 2: shadow framebuffer 把 lfb 换到错误地址（关键！）
- gfx.init 条件 `lfb >= 0x80000000 && info->shadow_buffer == 0` alloc heap shadow
- BGA fallback 用 lfb=0xE0000000（之前我写错）→ 触发 alloc shadow → present 写 shadow (低 RAM) → 但 QEMU 屏幕显示 0xE0000000 (BGA LFB) → 黑屏
- **VMM 已经把 0xE0000000 映射到页目录**（[VMM] VBE LFB mapped），kernel 直接写就 OK
- 修复: BGA fallback 设 `info->shadow_buffer = 1` 标记 "已映射,无需再 shadow" → init 不 alloc shadow
### Bug 3: BGA LFB 真实地址是 0xFD000000 不是 0xE0000000
- QEMU `info pci` 输出: VGA controller 1234:1111 BAR0 = **0xfd000000**
- BGA fallback 用 0xE0000000 → VMM 映射 0xE0000000 → 但 QEMU 实际 LFB 在 0xFD000000 → kernel 写到 0xE0000000 (不同地址) → 黑屏
- 修复: BGA fallback 改用 0xFD000000
