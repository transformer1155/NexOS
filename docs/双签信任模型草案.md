# 双签信任模型草案（可选可信层）

> 状态：草案 · 作者：ai-engineer · 目的：在**不破坏自编译自由**的前提下提供商业信任背书

## 1. 设计目标

1. 任何自编译 / 自签名镜像**都能启动**（开源承诺优先）。
2. 通过官方的镜像获得可验证的绿色标识，用于市场分发与企业采购。
3. 信任根集中但**不强制**：不接受它的人只是失去绿色标识，不失去系统。
4. 失败模式必须 fail-open（可启动 + 警告），而不是 fail-closed（变砖）。

## 2. 三种启动状态

| 状态 | 条件 | 外观 | 市场分发 |
| --- | --- | --- | --- |
| GREEN（官方认证） | 双签完整且根公钥匹配 | 绿色 Verified 标识 | 允许上架/推广 |
| DEVELOPER（开发者模式） | 签名缺失、自签名或根不匹配 | 红色警告，可一键确认 | 不允许以官方名义分发 |
| BROKEN（拒绝） | 镜像结构损坏 / 双签中 A 有效但 B 篡改 | 拒绝启动 | — |

注意第三档只用于**结构性损坏**，不用于「没签名」。没签名必须是 DEVELOPER。

## 3. 镜像签名格式

在每个可引导镜像尾部追加一个签名块（固定 512 字节，便于按扇区定位）：

    struct nexos_sig_block {
        uint32_t magic;        /* 'NSIG' 0x4753494E */
        uint16_t version;      /* 1 */
        uint16_t flags;        /* bit0 = A 有效, bit1 = B 有效 */
        uint8_t  payload_hash[32];  /* SHA-256(镜像正文) */
        uint8_t  signer_pubkey[32]; /* Ed25519 公钥，或 32B 指纹 */
        uint8_t  sig_a[64];    /* 开发者私钥签名 */
        uint8_t  sig_b[64];    /* 市场 CA 签名 */
        uint8_t  reserved[288];
    };

签名内容 = payload_hash || signer_pubkey（不签整个镜像，允许尾部签名块自身被追加）。

## 4. 校验流程（bootloader）

    1. 读镜像尾部 512B，magic 不对 -> 视为无签名 -> DEVELOPER
    2. 计算 payload_hash，与块内记录比较，不一致 -> BROKEN（明显损坏）
    3. 若 flags 含 A：用 signer_pubkey 验 sig_a，失败 -> BROKEN（声称签名但无效）
    4. 若 flags 含 A 且含 B：用**内置市场根公钥**验 sig_b，成功 -> GREEN
    5. 其余（无签名 / 只有 A / B 验不过）-> DEVELOPER

第 4 步的「根公钥」是唯一需要内置的东西。它是**可替换的构建选项**：

    make MARKET_ROOT_KEY=path/to/root.pub

不传该变量时，bootloader 不内置任何根公钥，所有镜像一律 DEVELOPER（纯开源构建）。

## 5. 开发者模式的行为

- 启动时串口与屏幕同时输出警告：

      当前系统包含未经官方认证的代码（开发者模式）。
      自编译镜像不受官方安全背书；请仅在你信任的构建上继续。

- 首次启动需要一次显式确认（写 MKFS 里的 developer_ack=1），之后不再打断。
- 不限制任何功能：MCP、AI、驱动加载全部照常。

## 6. 与可复现构建的关系

- 可复现构建验证的是「源码 → 二进制」一致性，与签名无关。
- 官方发布的 GREEN 镜像同时公布 `payload_hash`，任何人都可以自己构建并对比 hash。
- 这使「官方认证」不等于「必须信官方二进制」：hash 对得上即可。

## 7. 密钥与轮换

| 密钥 | 存放 | 轮换 |
| --- | --- | --- |
| 市场根私钥 | 离线 HSM，不联网 | 5 年，旧根保留用于验证历史镜像 |
| 开发者私钥 | 开发者本地 | 自主 |
| bootloader 内置根公钥 | 镜像 | 随系统更新，可同时内置新旧两把 |

bootloader 支持内置 **最多 2 把**根公钥（当前根 + 上一代根），避免轮换时旧镜像全部失效。

## 8. 未决问题

1. 是否需要在 DEVELOPER 模式下也校验 payload_hash（防意外损坏 vs 防篡改）？建议校验并提示。
2. 双签的 B 签名是否绑定版本号（防止降级回滚攻击）？建议绑定，签名内容加入 version。
3. 企业客户可能要求「只允许 GREEN 启动」的锁定模式，需要设计一个可恢复的开关（否则刷错就变砖）。
