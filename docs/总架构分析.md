# NexOS 架构设计白皮书 (Architecture Design Specification)

**版本**: 1.0.0-alpha
**内核类型**: 混合宏微内核 (Hybrid Monolithic-Microkernel)
**目标平台**: x86 / x86_64 (BIOS + UEFI)
**项目定位**: 面向 AI 开发者与独立游戏创作者的次世代原生操作系统

---

## 1. 系统概述 (System Overview)

NexOS 并非基于 Linux 或 Windows 内核的衍生物，而是一个完全从零构建的裸机操作系统。系统以 32 位/64 位双内核为底座，向外提供硬件抽象层（HAL）、动态驱动热加载框架、基于 MiniCLR 的 C# 托管运行时、原生大语言模型（LLM）推理引擎以及分布式算力网络。

本系统的核心设计哲学是：**“微内核化驱动热加载”**、**“双语言边界（C/C++ 底层 + C# 上层）”** 与 **“AI 原生总线（MCP）”**。

---

## 2. 核心子系统拓扑 (Subsystem Topology)

系统采用严格的层级架构，自底向上分为五个核心层：

```text
[ 应用与生态层 ] Nexpack 应用 | Win32/PE 兼容层 | Linux ELF 兼容层 | C# 托管应用
       ↓
[ 服务与总线层 ] MCP (Model Context Protocol) 总线 | 分布式算力网络 (Distnet) | HTTP 网络服务
       ↓
[ 运行时环境层 ] MiniCLR (C# Runtime) | GGUF 大模型推理引擎 | C# 图形壳 (NexOS.Forms)
       ↓
[ 核心内核层   ] 内存管理(VMM/PMM) | 调度器 | 权限沙箱 | 动态驱动加载器 | 原生 GUI 合成器
       ↓
[ 硬件抽象层   ] BIOS/UEFI 引导 | 32/64位模式切换 | ATA/NE2000/VBE 驱动 | 中断/异常处理
```

---

## 3. 底层地基：引导与核心内核 (Boot & Kernel)

### 3.1 双阶引导 (Two-Stage Bootloader)
*   **Stage 1**: 驻留 `0x7C00`，从磁盘读取 Stage 2 并跳转。
*   **Stage 2**: 完成 A20 门开启、GDT 加载，将 `kernel.bin` 加载至 `0x10000`，切入 32 位保护模式。
*   **UEFI 兼容**: 通过 `bootuefi.c` 提供 UEFI 路径，从 GOP 帧缓冲接管显示，实现与 BIOS 路径的统一汇合。

### 3.2 双内核与模式切换
*   **32 位内核 (`kernel.bin`)**：主控内核，负责基础渲染、输入、以及 C# 运行时的宿主托管。
*   **64 位内核 (`kernel64.bin`)**：长模式内核，负责重型计算（如 GGUF 推理）。通过 `switch32to64.asm` 在运行时无感切换。

### 3.3 虚拟内存与堆管理 (VMM & PMM)
*   基于 x86 PSE 机制的分页系统。
*   支持动态扩容的内核堆（当前上限 128MB），采用连续物理内存映射，规避传统微内核的碎片化问题。

### 3.4 动态驱动加载器 (Dynamic Driver Loader)
*   摒弃传统的静态链接驱动。
*   实现了一个 C 语言编写的 ELF 解析器，能够从文件系统读取 `.drv` 文件。
*   支持符号重定位、API 导出表注册、执行初始化（`init`）。
*   具备**安全回滚机制**与**资源强制回收**（防驱动卸载后悬挂指针）。

---

## 4. 存储与安全隔离 (Storage & Security)

### 4.1 双生文件系统 (Dual File System)
*   **MKFS**: 自研可写文件系统，支持独立数据盘持久化，存储用户配置、密码哈希（`shadow`）及权限库。
*   **SFS**: 只读系统文件系统，用于承载只读系统资产（如 `.mex` 应用、字库等）。
*   底层 VFS 层具备 `E-ROFS` 硬拦截，防止对 SFS 的非法写入。

### 4.2 安全网关与防御引擎 (Security Gateway)
*   提供底层级的系统防护能力，专门针对高级木马（如银狐）。
*   具备 NTFS 隐藏属性剥离、注册表高权限改动监控。
*   接管系统电源事件 (`WM_QUERYENDSESSION`)，防范恶意软件中断防御进程。

---

## 5. 图形与 UI 合成层 (GUI & Render)

### 5.1 原生帧缓冲合成器 (Framebuffer Compositor)
*   基于 VBE/GOP 直接操作物理帧缓冲。
*   支持脏矩形局部重绘（Dirty Rectangles）、抗锯齿文本、SDF 圆角渲染与毛玻璃（Acrylic）特效。

### 5.2 C# 托管图形壳 (NexOS.Forms)
*   核心创新点：UI 层不是用 C++ 写的，而是通过 MiniCLR 运行 C# 代码。
*   底层通过 `InternalCall` 将 `Gfx.FillRect`、`Gfx.DrawText` 等指令桥接给 C++ 渲染引擎。实现了开发效率与运行性能的完美平衡。

---

## 6. AI 原生架构 (AI-Native Architecture)

NexOS 是首个将大语言模型推理与 Agent 总线下沉至操作系统底层的项目。

### 6.1 本地推理引擎 (GGUF Inference)
*   内核集成 Qwen2-0.5B 量化模型。
*   包含完整的 Transformer 前向传播逻辑（Attention、RoPE 等），支持在长模式下流式输出。

### 6.2 MCP (Model Context Protocol) 总线
*   **设计目标**：让 AI Agent 接管操作系统。
*   将系统的文件、终端、网络、UI 操作封装为标准化的 MCP Tools。
*   AI 可以通过自然语言语义，直接调用底层系统资源。

### 6.3 聚合算力网关 (BYOK Gateway)
*   底层统一管理各平台（DeepSeek、OpenAI 等）的 API 路由与用户的私有 Key。
*   向上层应用（如游戏、编辑器）提供零成本的 AI 算力调用接口。

---

## 7. 分布式与网络栈 (Network & Distnet)

*   **完全独立的网络栈**: 手搓 TCP/IP、DNS、HTTP 服务器，底层直驱 NE2000 网卡。
*   **Distnet 分布式算力**: 基于 UDP 广播的节点发现机制。支持模型分片、任务下发、中间激活值传输（AACT）以及掉线容错重分片。
*   **VNC 远程桌面**: 原生 RFB 3.8 客户端，支持将 Linux 虚拟机的图形画面嵌套渲染至 NexOS 窗口内。

---

## 8. 应用生态与兼容性 (Ecosystem & Compatibility)

### 8.1 生态包格式 (`.nexpack`)
*   类似 VS Code 插件体系的第三方应用分发格式。
*   由宿主侧解包、合并注册表，内核侧完成安装读取。

### 8.2 多语言兼容层
*   **Win32/PE 子系统**: 自研 PE 加载器与 Win32 API 映射，支持直接运行 Windows `.exe`。
*   **Linux 兼容层**: 支持加载 Linux ELF 动态链接程序。
*   **MiniCLR**: 自研 .NET 托管环境，支持标准 C# 字节码。

---

## 9. 开发者工具链 (Dev Toolchain)

*   **微任务流水线 (Micro-Task Pipeline)**: 基于 DSH 插件的自动化开发流。将极简上下文交给 LLM 生成函数，配合快速编译（`fastverify.sh`），极大提升 AI 辅助开发效率。
*   **镜像守卫**: 自动校验 `kernel64.bin` 的 LBA 偏移，防止静默截断覆盖 SFS 镜像。
