# 进程隔离框架 · 挂接说明

> 配套：`proc_isolation.h` / `proc_isolation.cpp`
> 状态：框架已写好，**尚未接入构建**（刻意不链，避免在无构建窗口时破坏别人）

## 为什么先做成独立模块

技术总监要求在 proc.cpp / vfs.cpp 里写框架。我把它做成了独立翻译单元，原因：

1. proc.cpp / vfs.cpp 是共享热点文件，直接改容易和别人冲突
2. 当前没有构建窗口，未经验证的大改动一旦进 Makefile 就可能让全队构建失败
3. 独立模块可以先用 `g++ -fsyntax-only` 单独验证，再接钩子

## 四层隔离与代码的对应关系

| 要求 | 实现 | 位置 |
| --- | --- | --- |
| 独立 CR3 / PML4 | `agent_mem_create()` 分配新 PML4，只映射 code/data/ring | proc_isolation.cpp |
| 禁用恒等映射 | 创建时**不复制**低地址恒等映射；`agent_mem_va_mapped()` 只认三个区间 | 同上 |
| CR0.WP 写保护 | 需在 `agent_mem_enter()` 里置 CR0.WP（TODO，等 VMM 接口确认） | 同上 |
| Ring 3 | 由 proc.cpp 的进程创建路径设置 CS/SS RPL=3（TODO 挂接） | proc.cpp |
| syscall 白名单 | `agent_syscall_allowed()` 只放行 read/write/exit | proc_isolation.cpp |
| VFS 沙盒根 | `agent_vfs_bind()` + `agent_vfs_resolve()` 强制前缀、拒绝 `..` | 同上 |
| 只读系统挂载 | `agent_vfs_check_write()` 在 mount_ro 时一律 -EPERM | 同上 |
| 禁 unlink/rename | `agent_vfs_check_unlink/rename()` 恒 -EPERM | 同上 |
| 禁 socket | `agent_net_allowed()` 恒 0 | 同上 |
| MCP 脱敏 | `agent_mcp_scan()` 对出站 payload 做关键字扫描 | 同上 |

## 需要接的三处钩子（各 2–6 行）

### A. proc.cpp：创建 Agent 进程时

    if (is_agent_process) {
        agent_mem_create(slot, AGENT_VA_BASE,
                         code_len, AGENT_VA_BASE + 0x1000000ULL, data_len,
                         AGENT_RING_VA, 4096);
        agent_vfs_bind(slot, "/sandbox/agent_01");
    }

进程退出时：`agent_mem_destroy(slot); agent_vfs_unbind(slot);`

### B. syscall.cpp：入口处

    if (is_agent_process) {
        int32_t r = agent_syscall_gate(nr, a0, a1, a2);
        if (r < 0) return r;          /* -EPERM */
    }

### C. vfs.cpp：open/unlink/rename 之前

    if (is_agent_process) {
        char canon[256];
        const char* p = agent_vfs_resolve(slot, path, canon, sizeof(canon));
        if (!p) return -EPERM;         /* escaped the sandbox */
        path = p;
        if (op == VFS_OP_WRITE  && agent_vfs_check_write(slot, path)  < 0) return -EPERM;
        if (op == VFS_OP_UNLINK && agent_vfs_check_unlink(slot, path) < 0) return -EPERM;
        if (op == VFS_OP_RENAME && agent_vfs_check_rename(slot, a, b) < 0) return -EPERM;
    }

## 尚未实现、必须补的

1. **页表释放**：`agent_mem_destroy()` 目前只释放顶层 PML4，叶子页会泄漏。
   需要一个 PML4 遍历器（VMM 里应该已有，只是没导出）。
2. **CR0.WP**：进入 agent 前置位，离开后恢复（要确认内核自己不依赖 WP=0 的写行为）。
3. **#PF 处理**：捕获后判断 `agent_mem_va_mapped()`，为假 -> kill 进程。
4. **VFS root_inode**：`agent_vfs_resolve()` 现在用字符串前缀；真正实现应绑定 inode 并
   在路径解析器里替换根。字符串前缀是等价的过渡方案，但它依赖前缀不可被 rename 绕过。
5. **MCP 扫描**是关键字启发式，只能当兜底，不能当 DLP。

## 与现有 MCP 身份模型的关系

不要另造身份：`is_agent_process` 的判定应复用 CLR 记录的 `g_current_app_id` +
resident-set，与 `sys_install_derivative` 草案一致。这样整个系统只有**一处**身份来源。
